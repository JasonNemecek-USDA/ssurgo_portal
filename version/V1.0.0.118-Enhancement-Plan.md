# SSURGO Portal v1.0.0.118 Enhancement and Hardening Plan

## Planning Mode
This plan intentionally assumes nothing is complete yet.
Previously completed or partial work is ignored by design.
All items below are treated as future todo work for .118.

## Mission for v1.0.0.118
1. Make nationwide downloads and imports fast enough to feel responsive at full scale.
2. Make runs fool-proof: no silent stalls, no unknown failures, clean recovery paths.
3. Improve user experience for large jobs and long-running operations.
4. Add a secure EXE distribution path for Software Center while keeping the auto CMD path.
5. Pass strict USDA CEC OCIO security and packaging expectations.

## Scale Target
The platform must handle a full run across:
- CONUS
- Alaska
- Hawaii
- Puerto Rico
- US territories and outlying areas
- Palau
- American Samoa
- Additional island/outlying datasets as configured

## Success Criteria
1. End-to-end full-scale run completes with complete accounting for every selected survey area.
2. No silent hangs: every stall condition is detected, surfaced, and recoverable.
3. Resume after interruption from last checkpoint without redoing completed areas.
4. Performance objective: full national manifest p95 <= 30 minutes across managed Python runtime fallback paths.
5. Security objective: EXE package is signed, scan-clean, policy-compliant, and deployable in Software Center.

## Workstreams

### A) Performance and Scale
- Improve throughput for download, save, unzip, and database build stages.
- Add adaptive control loops so throughput remains high under changing network and disk conditions.
- Reduce UI overhead under thousands of status updates.

### B) Reliability and Error Coverage
- Add full error taxonomy and stage-aware reporting.
- Guarantee each area ends in success or explicit categorized failure.
- Add watchdog and self-healing behavior for stalled pipelines.

### C) User Experience and Usability
- Better progress visibility, ETA, summary reporting, and one-click rerun of failures.
- Better preflight guidance before full-scale jobs.

### D) Security, Compliance, and Best Practices
- Build security gates into CI and release process.
- Produce compliance evidence package for USDA CEC OCIO review.

### E) Packaging and Distribution
- Keep auto CMD launcher workflow.
- Add EXE workflow as second release artifact.
- Add PKG folder with install.com and executable payload.

## Recommended Execution Sequence
1. Complete Phase 0 first to prevent guessing and rework.
2. Execute Phases 1 to 4 in parallel tracks where possible.
3. Start Phase 7 early for packaging/compliance lead time.
4. Run Phase 6 continuously as release gates, not end-stage tasks.
5. Finish with Phase 8 acceptance runs and sign-off.

## Suggested Milestones
- Milestone M1: Baseline + first speed gains + no silent stall detection.
- Milestone M2: Resume/checkpoint + full error taxonomy + robust diagnostics.
- Milestone M3: National-scale ingest speed target reached.
- Milestone M4: EXE packaging and Software Center pilot ready.
- Milestone M5: Full compliance and production release readiness.

## Risks and Mitigations
1. Risk: Full-run performance still limited by external upstream service latency.
   - Mitigation: isolate network bottleneck metrics, optimize local stages aggressively, maximize resilience and resume.
2. Risk: UI appears stalled while backend still runs.
   - Mitigation: heartbeat status model and bounded UI rendering.
3. Risk: Compliance work discovered late.
   - Mitigation: shift-left security gates and evidence bundle from early milestones.
4. Risk: EXE deployment issues in managed endpoints.
   - Mitigation: pilot with detection logic and silent install validation before broad rollout.
