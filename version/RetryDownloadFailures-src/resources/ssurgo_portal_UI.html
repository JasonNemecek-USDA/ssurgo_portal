Left Pane Menu

The Left Pane Menu allows you to do the following:

  1. Select an existing SQLite SSURGO Template database or create a new SQLite SSURGO Template database.
  2. Select the location of SSURGO data.
  3. Import SSURGO data into SSURGO SQLite Template database.
  4. Delete existing SSURGO data from an SQLite SSURGO Template database.
  5. Select Advanced Options prior to importing for special use cases.

Step 1: Select or Create a Database

The SQLite SSURGO Template database needs to be identified before any data can be imported to or deleted from a database. In this step, you select an existing SQLite SSURGO Template database or create a new SQLite SSURGO Template database. Clicking “Browse” takes you to another screen to select an existing database or create a database. After you select or create a database, you are returned to the main screen, and the label above the step 1 box has changed to “Change or Create a Database.”

Refer to the help menu on the Select or Create a Database page for more information.

Step 2: Select Folder of SSURGO Data

SSURGO Portal needs to know the location of your local folder that contains SSURGO data (i.e., SSURGO data packages) before data can be imported into the template database. In this step, you identify the location of the folder that contains SSURGO data. Clicking “Browse” takes you to another screen to select the location of the folder containing your SSURGO data. After selecting the location, you are returned to the main page, and the label above the step 2 box has changed to “Change Location of SSURGO Data.”

Refer to the help menu on the Select Folder of SSURGO Data for more information.

SSURGO data packages are typically acquired by downloading them as zip files from Web Soil Survey. The downloads must be unzipped to your local folder before you can begin importing SSURGO data.

This folder can be named anything, created anywhere, and may contain many SSURGO data packages (i.e., many downloads from Web Soil Survey). It is strongly recommended that you only have SSURGO data in this folder. After selecting the location, a hidden series of quality assurance pretests are run against your SSURGO data to ensure it has the correct schema. See Pretests section of the help menu for more information about these checks.

Types of SSURGO Data

Two types of SSURGO data packages are available for download on Web Soil Survey, and SSURGO Portal will support both.

Standard SSURGO data package
  • Delivered for a single soil survey area.
  • Soil survey areas are typically delivered for each county in the United States, but some soil survey areas span multiple counties because they are designed for special areas, such as tribal owned lands, National Parks, or National Forests.
Area of Interest data package
  • Web Soil Survey allows users to create custom AOIs and then download SSURGO for that AOI.
  • AOI SSURGO is only available for download after an AOI is created on Web Soil Survey.
  • AOI SSURGO can include portions of more than one soil survey area.
Note for USDA employees, SSURGO Portal supports internal USDA SSURGO exported from the National Soil Information System (NASIS) database and SSURGO data downloaded from the Staging Server. However, this requires you to reformat spatial data and create some additional folders before importing this SSURGO data.

Import SSURGO Data

SSURGO data is only able to be imported after a template database has been selected, the location of the SSURGO data is identified, and at least one record is selected in the “Import SSURGO Data” table. The “Import SSURGO Data” button is only visible when you are viewing the “Import SSURGO Data” table in the main window. Clicking this button initiates the import process of any selected SSURGO data into the selected template database. After you click this button, you are taken to another screen that shows the status of the import process.

Area Symbol Validations

SSURGO data is organized by soil survey areas, and each survey area has a unique area symbol. Duplicate area symbols are not allowed in the SQLite SSURGO Template Database, and SSURGO Portal detects instances of duplications. If duplications are selected and the “Import SSURGO Data” button is clicked, an error message will appear.

When importing SSURGO data, two area symbol validation checks are executed prior to the start:

  1. SSURGO Portal reviews the selected template database to see if any of the area symbols you are trying to import already exist in the database.
    • For example, you are trying to import area symbol OR021, but OR021 is already in your template database. If this occurs, you will receive a warning message with the option to proceed. Proceeding with the import will delete the existing version of OR021 in the template database and replace it with the new one.
  2. SSURGO Portal reviews the SSURGO data you are trying to import for duplicate area symbols.
    • For example, the SSURGO data you selected for import somehow has two instances of area symbol OR021.
      • Initially, the duplicated data will be flagged in the “Import SSURGO Data” table, and a warning message will appear at the top of the table.
      • Subsequently, if you attempt to import both instances of OR021 you will receive an error message.
SSURGO contains version dates, which are the dates the data is published. It is recommended that you consider the version dates of the two area symbols and the Exists in Database column when reconciling duplicate area symbols. Typically, you will want the area symbol with the most current version date.

Advanced Options

You can typically ignore advanced options. These options are rarely used and are designed for special use cases.

They are only visible when you are viewing the “Import SSURGO Data” table in the main window.

There are three advanced options:

  1. Load Tabular Data Only
  2. Disable Dissolve
  3. Include Interpretation Sub Rules

Load Tabular Data Only

By default, SSURGO Portal imports spatial and tabular SSURGO into the selected template database. Selecting this option will only import the SSURGO tabular data. This option was mainly included for internal USDA employees who have special use cases that require tabular only data. However, anyone can use it.

Disable Disolve

By default, the polygons in the soilmu_a_XXXX.shp file are dissolved on the “MUKEY” column during import. Selecting this option removes the dissolving function.

Dissolving significantly reduces the number of records in the SQLite SSURGO Template database mupolygon table and improves performance of this layer in GIS software. Removing the dissolve will increase the database sizes. It will also make draw times, joins, relates, and selections take longer in GIS.

Dissolving does not result in any data loss.

Load Interpretation Sub Rules

By default, the sub rules used to create soil interpretations are not imported. Selecting this option will import the sub rules.

Soil interpretations reside in the component interpretation table (i.e., cointerp table). The interpretations consist of a main parent rule and a series of sub rules (i.e., child) nested on the main rule. The main rule is the final interpretation rating for a component, and main rules always are included during the import process. The sub rules were used to create the final rating and can provide information about what drove the final rating. Typically, they are not needed, and by default, SSURGO Portal does not import the sub rules.

Including them will not affect the data, but it will increase the size the template database by 150%, slow import times, and negatively impact the user experience when working the component interpretation table.

Delete SSURGO Data

This button is only visible when you are viewing the “SSURGO Data in Database” table in the main window. It initiates the delete of SSURGO data that was selected in the SSURGO data in Database table. The selected SSURGO data will be completely deleted from the SQLite SSURGO Template database. Deletes are final, and there is no option to undo a delete.

Clicking this button takes you to another screen that shows the status of the delete process.

SSURGO data is grouped by area symbols, and when you delete an area symbol, you delete all data associated with that area symbol. For example, area symbol OR021 is used for the Gilliam County, Oregon, SSURGO data. The OR021 area symbol contains numerous tabular and spatial tables, and when you delete OR021, you delete all data associated with OR021.

Main Window

The main part of the screen, or the main window, allows you to do the following:

  1. Select SSURGO data for import into the SQLite SSURGO Template database.
  2. View and delete the contents of the SQLite SSURGO Template database.

Import SSURGO Data Button

The “Import SSURGO Data” table is empty by default. The table will become populated after you complete step 2 on the Left Pane Menu and after Pretests are run against the folder selected in step 2.

The “Import SSURGO Data” table displays all valid SSURGO Soil Survey Areas (SSAs) that are present in your SSURGO data folder. You can use this table to select SSAs that you would like to import into your SSURGO database. If you want to select all SSAs for import, click the “Select All” checkbox at the top left of the table. After you make your selections, click the “Import SSURGO Data” button to begin the import process.

The “Import SSURGO Data” table contains seven columns, which are listed and defined below:

Import SSURGO Data Columns

The seven columns in the “Import SSURGO Data” table provide information about the names, symbols, and version dates of the SSURGO data being considered for import into the template. They also identify instances where data already exists in the database.

  1. Select or Deselect
    • This column allows you to select or deselect SSURGO data for import into the SQLite SSURGO Template database.
    • Click the check box to select or deselect SSURGO data.
    • A check mark icon will appear when you have selected SSURGO data, and the check mark is absent when it is deselected.
    • SSURGO data is deselected by default.
    • You can click the box at the top of this column to select or deselect all SSURGO data in the table.
  2. Folder Name
    • This is the name of the folder that contains the SSURGO spatial and tabular data.
    • This folder is a child folder of the directory you selected in step 2 on the Left Pane Menu. Put another way, it exists inside the folder selected in step 2.
    • For standard SSURGO downloaded from Web Soil Survey (non-AOI SSURGO), the folder name will typically be the area symbol for the SSA, and it will match the area symbol in column 3. However, this folder can be named anything.
    • For AOI SSURGO (non-standard SSURGO), the folder name will start with wss_aoi_ and will be followed by a date. For example, “wss_aoi_2022-04-29_14-31-23”. This folder can be named anything.
  3. Area Symbol
    • This is the official area symbol used for the soil survey area.
    • This area symbol is derived from the areasymbol column in the sacatalog table, which resides in the tabular folder.
    • If more than one area symbol exists in a single SSURGO data package, you will see one folder name in column 2 and multiple area symbols in this column.
    • For standard SSURGO downloaded from Web Soil Survey (non-AOI SSURGO), the folder name in column 2 will typically be the area symbol and will match the area symbol in this column.
    • For AOI SSURGO (non-standard SSURGO), the area symbol(s) will appear in this column, and it will NOT match the folder name in column 2.
  4. Area Name
    • This is the official area name for the SSURGO data that exists in the folder listed in column 2.
    • This area name is derived from the areaname column in the sacatalog table, which resides in the tabular folder.
  5. Folder SSURGO Version Date
    • The version date is the date the SSURGO data package was published. It is the date for the SSURGO data that resides in the folder you identified in step 2.
    • Each area symbol can have a unique version date.
    • The date is derived from the saversion column in the sacatalog table, which resides in the tabular folder.
  6. Exists in Database
    • This column is used to indicate if an area symbol already exists in the SQLite SSURGO Template database. If the area symbol exists, one of two possible symbols appears in the column.
    • The green check mark indicates that the area symbol exists in the template database and the version date in the template matches the version date of the SSURGO data in the folder you selected in step 2.
    • The yellow warning icon indicates that the area symbol exists in the template database and the version date in the template DOES NOT match the version date of the SSURGO data in the folder you selected in step 2.
    • If no icon appears in the column, it means the area symbol is NOT in your selected template database.
    • If an area symbol exists in the template, and you proceed with importing the same area symbol, it will delete all SSURGO data from the template for that area symbol and replace it with the data you selected for import.
  7. Database SSURGO Version Date
    • This is the version date of the SSURGO data that already exists in your SQLite SSURGO Template database. The version date is the date the SSURGO data was published.
    • Each area symbol can have a unique version date.
    • The date is derived from the template database saversion column in the sacatalog table, which resides in the tabular folder.
    • A date only appears in this column if an area symbol in column 3 (area symbol column) already exists in the template database. If it does not exist in the template, the column is left blank.

Pretests

When the folder containing SSURGO data is selected or changed on the Left Pane Menu, a series of pretests are run against the contents of the folder. The pretests identify any data that will fail during the import process ahead of time. The tests evaluate all child folders in the selected SSURGO data folder and flags any folders that fail one of the following validations:

  1. Missing tabular folder. a
  2. Missing sacatalog.txt file in tabular folder.
  3. SSURGO version in version.txt, in tabular folder, does not match SQLite SSURGO Template SSURGO version.
  4. Missing spatial folder. a, b
  5. Coordinate system of data in the spatial folder is not WGS84 (EPSG 4326). b
  6. Empty sapolygon in the spatial folder. b
  7. Empty mupolygon layer in the spatial folder. b
a Folder name must be lowercase.
b This pretest does not run when “Load Tabular Only” is selected in the Advanced Options.

The “Import SSURGO Data” table only displays those folders that pass the pretests. Any folder that fails the pretests will be identified in the error list at the top of the table. If an error list is not shown above the table, all of your folders passed the pretests.

Duplicate Area Symbol Precheck Warnings

When the folder containing SSURGO data is selected or changed on Left Pane Menu, the SSURGO data is evaluated for instances of duplicate area symbols. Area symbols must be unique in the SQLite SSURGO Template Database, and this evaluation alerts you if an area symbol is duplicated in the folder containing SSURGO. If a folder with a duplicate area symbol is detected, a warning message is presented at the top of the table, but the area symbols are still presented in the Import SSURGO data table. These folders will also display a warning message in the Folder Name column.

Refresh Import SSURGO Data Table

When the folder containing SSURGO data is selected or changed on Left Pane Menu, SSURGO Portal runs the pretests against the selected SSURGO data folder again. If you make modifications to the data (i.e., update, add, or delete) in your SSURGO data folder outside of the application, the application will not automatically notice your changes. To refresh the User Interface, you must click the “Refresh” button next to the “Import SSURGO Data” button in the main window. This will also re-execute pretests and will reflect the modifications you made to your SSURGO data folder.

SSURGO Data in Database

This table presents you with an inventory of any SSURGO data that exists in your selected SQLite SSURGO Template database, and it allows you to delete SSURGO data from your selected database. The table is empty by default. To populate the table, you need to either import data into your selected database from the “Import SSURGO Data” tab or select a database that already contains SSURGO data.

You can delete one or more SSURGO soil survey areas from a template database by checking the box on the left side of the table and then clicking the “Delete SSURGO Data” button, which is located on the Left Pane Menu. If you want to delete all SSURGO data in your selected database, you can check the box at the top left of the table to select all SSURGO data in the database.

Selecting all SSURGO data in your database and clicking the “Delete SSURGO Data” button on the Left Pane Menu will result in a warning pop-up. Click the “Continue” button on the pop-up to delete all data.

While you can delete all data in the template database, it is recommended you instead create a brand-new empty template database.

The “SSURGO Data in Database” table contains five columns, which are listed and defined below.

SSURGO Data in Database Columns

The five columns in the “Import SSURGO Data” table provide information about the names, symbols, and version dates of SSURGO data that exists in the SQLite SSURGO Template database. They also identify instances where data already exists in the database.

  1. Select or Deselect
    • This column allows you to select or deselect SSURGO data for deletion from the SQLite SSURGO Template database.
    • Click the check box to select or deselect SSURGO data.
    • A check mark icon will appear when you have selected SSURGO data, and the check mark is absent when it is deselected.
    • SSURGO data is deselected by default.
    • You can click the box at the top of this column to select or deselect all SSURGO data in the table.
  2. Area Symbol
    • This is the official area symbol used for the soil survey area.
    • This area symbol is derived from the areasymbol column in the sacatalog table in the template database.
  3. Name
    • This is the official area name for the SSURGO data that exists in the folder listed in column 2.
    • This area name is derived from the areaname column in the sacatalog table in the template database.
  4. SSURGO Version Date
    • This is the version date of the SSURGO data in the template database. The version date indicates the date the SSURGO data was published by the USDA.
    • Each area symbol can have a unique version date.
    • The date is derived from the saversion column in the sacatalog table, which is in the template database.
  5. Tabular Only
    • If a blue check mark appears, then only tabular data exists for the area symbol.
    • Typically, this column will be empty.
    • SSURGO data is composed of both tabular and spatial data, and typically, both tabular and spatial data are imported into the SQLite SSURGO Template database for a given area symbol. However, special use cases exist where you may only require tabular data, and the spatial data is omitted.

Page Overview

SSURGO Portal requires the location of an SQLite SSURGO template database before any SSURGO data can be imported or deleted from a template database. This page allows you to create a new template database or identify the location of an existing template database. Normally, if it is the first time you are suing SSURGO Portal, you will need to create a new template database and place it in a folder of your choice, thus identifying the location. However, other use cases exist where you will want to select a preexisting template database and identify its location.

You must complete the following two steps on this page to identify the location of an SQLite SSURGO template database:

  1. Set File Path of the Folder where the new template database will be located or where the existing template database is located.
  2. Do one of the following:
    • Create a new template database, which will add it to the folder identified in step 1.
    • Select an existing template database from a folder identified in step 1.
After you complete step 2, you are returned to the original landing page and can proceed to the importing or deleting SSURGO data.

Set File Path of Database

This section allows you to identify the path to the folder where an existing template database is located or where the new database will be created. The folder contents will be displayed in the table below this section. Only folders and files with the .gpkg or .sqlite extensions will appear in the table. The GeoPackage version of the SQLite SSURGO Template database uses the .gpkg extension, and SpatiaLite version uses the .sqlite extension.

Upon initial use, SSURGO Portal will default the path to the C drive. Upon subsequent use, SSURGO Portal will default the path to the location identified the last time the application was used. This path will default back to the C: drive when your browser cookies are cleared.

You can change the path one of three ways:

1. Manually edit file path

To manually edit the path, click on the pencil icon located on the far right of the file path. After clicking the pencil icon, you either type or paste in a new path. When you are done editing the file path, click the black X on the far right to complete the change.

This is also where you can change the drive letter. Upon initial use, the application defaults to your C: drive, but you can manually change it any other drive letter (e.g., D:\, E:\).

2. Browse through folders in the table below this section to move forward

You can change the path by clicking on folders in the table below this section.

3. Click on folder names or drive letter within the path to move backwards

You can click on any folder name or the drive letter within the file path to move back through folders. For example, you see the file path C: > SSURGO Poral > Databases > Oregon. This path will show you the contents of the Oregon folder in the table below, but you can click directly on the word Databases in the path name to change location to C: > SSURGO Portal > Databases.

Create a New Database

To create a new database, click the button at the bottom of the page titled “Click to Create New Database.”

A pop-up window titled “Create New Database” will appear after clicking this button. This window allows you to choose the database type and name the database.

New Database Name

You can enter any name, and you do not need to enter the file extension. If the name you enter already exists, you will be presented a warning message and with the option to override the existing database.

Choose Database Type

Two options are presented for database type:

  1. SpatiaLite
  2. GeoPackage

Both template types are valid options, and you will not notice much difference in the resultant database. However, SpatiaLite and GeoPackage contain different schemas designed for storing spatial data in a template database. This means they have different sets of tables and columns required for storing spatial information. Currently, SSURGO Portal includes both schemas for those familiar with SQLite files. SpatiaLite is the older schema, and GeoPackage is the newer schema.

Internal NRCS Employee Options

This section is rarely used, and it is only intended for internal USDA-NRCS staff. It allows you to select special versions of the SQLite SSURGO Template database. In these special versions, most primary keys are defined as TEXT data type. This contrasts with the normal templates, where the primary keys are almost entirely INT data type. These special versions are designed explicitly for SSURGO data created from the non-public facing NASIS and Staging databases (i.e., Staging Server). Due to database schemas, SSURGO data from these two databases creates numerous primary keys with colons, and these keys must be defined as a TEXT data type. For example, a key value may look like 895671:674348.

To create these special versions:

  1. Click “Internal NRCS Employee Options” at the bottom right of the page.
  2. Check the box next to “Click to enable database options for SSURGO from NASIS or Staging Server before creating a new database.”
  3. Click the button labeled “Click to Create New Database” on the bottom left of the page.
    • The special versions for SSURGO NASIS and Staging Server will be presented in the “Choose Database Type” drop list, and the normal versions will not be listed.
    • You can identify the special versions because they include “for SSURGO from NASIS or Staging” in parentheses.
To make the normal versions available again, close the “Create New Database” window, and uncheck the box next to “Click to enable database options for SSURGO from NASIS or Staging Server before creating a new database.” The normal versions will appear the next time you click “Click to Create New Database” button.

Once you have named a database and selected the database type, click the “Save Database” button. This will create the new database in the file path you selected, and it will return you to the main page.

Select an Existing Database

To select an existing SQLite SSURGO Template database, browse to the location of the database and select it from the table. This preexisting database can be empty, or it can already contain SSURGO data.

After you select the existing database by clicking on it in the table, you will be returned to the main page.

Example of Creating Folder, Unzipping SSURGO, and Selecting Location of SSURGO Data

  1. You create a local folder called “SSURGO Downloads” on your C: drive.
  2. You download a SSURGO data package from Web Soil Survey for OR021 Gilliam County, Oregon, and place the zip file in “C:\SSURGO Downloads.”
  3. You unzip the SSURGO data package to the “C:\SSURGO Downloads” folder.
    • You will see a new “OR021” folder in “C:\SSURGO Downloads” after unzipping.
    • If you open the “OR021” folder, you will see a “spatial” and “tabular” folder, which contain the spatial and tabular SSURGO data.
    • The data is now ready for import into the template database.
  4. In SSURGO Portal, on the “Select Folder of SSURGO Data” page, you set your file path to C: > SSURGO Downloads.
    • OR021 will appear in the table below.*
  5. In SSURGO Portal, on the “Select Folder of SSURGO Data” page, click the “Click here to finalize file path of SSURGO data” button below the table.
    • This will return you to the main landing page.
* If you see folders named “spatial” and “tabular” in your table, you probably drilled too far down into the file path, and you need to go up one folder. If you select an incorrect folder, you see the correct SSURGO data or any SSURGO data available for import when you return to the main page.

Types of SSURGO Data

Two types of SSURGO data packages are available for download on Web Soil Survey, and SSURGO Portal will support both.

1. Standard SSURGO data package

  • Delivered for a single soil survey area.
  • Soil survey areas are typically delivered for each county in the United States, but some soil survey areas span multiple counties because they are designed for special areas, such as tribal owned lands, National Parks, or National Forests.

2. Area of Interest (AOI) SSURGO data package

  • Web Soil Survey allows users to create custom AOIs and then download SSURGO for that AOI.
  • AOI SSURGO is only available for download after an AOI is created on Web Soil Survey.
  • AOI can include portions of more than one soil survey area.
Note for USDA employees, SSURGO Portal also supports internal USDA SSURGO exported from the NASIS database and SSURGO data downloaded from the Staging Server. However, this requires you to reformat spatial data and create some additional folders before importing this SSURGO data.
